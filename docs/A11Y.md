# Accessibility — audit approach & status

> bSmart Works targets **WCAG 2.2 AA** (iteration 20, Cap A). This document describes the
> accessibility audit programme: what is **automated** (and where), what still requires a
> **manual** pass, and a **per-surface checklist** for the remaining manual audit.
>
> Owner: frontend · Tracking issue: **#276** · First increment landed: the automated axe harness +
> Insights-surface remediation (this PR).

---

## 1. The layered approach

Automated tooling catches roughly **30–40%** of WCAG success criteria. The rest — anything that
depends on layout, real rendering, focus order, narration, or human judgement — must be checked by
a person. We run accessibility checks at four layers, each owning what it can actually verify:

| Layer | Tool | Runs | Catches |
|-------|------|------|---------|
| **Lint** | `eslint-plugin-jsx-a11y` | save · pre-commit · CI | static JSX a11y mistakes (missing `alt`, label-less controls, bad ARIA props, non-interactive handlers) |
| **Unit a11y** | **axe-core** via `expectNoA11yViolations` (this PR) | Vitest + jsdom · CI | rendered-DOM violations: names/labels, roles, ARIA validity/required-children, heading order, list/table structure, duplicate ids, button/link text |
| **Component a11y (real browser)** | `@storybook/addon-a11y` (already a dep) | Storybook / `storybook:build` | the above **plus** real-browser **colour contrast** and computed-style rules jsdom can't evaluate |
| **Manual audit** | screen reader + keyboard + zoom | per release / per surface | everything below in §3 — narration, traversal order, focus-visible appearance, reflow, target size, motion |

### What the axe harness deliberately does **not** check (jsdom limits)

jsdom has no layout engine or computed colour, so two rule families are turned **off** in the unit
harness (`works-frontend/src/test/a11y.js`) and are owned by the real-browser + manual layers
instead:

- **`color-contrast`** — needs computed colour + layout. Verified in Storybook addon-a11y and the
  manual audit against the design tokens (RB-30 §2: never `neutral-400` for readable text).
- **`target-size`** (WCAG 2.2, 2.5.8 — 24×24 CSS px minimum) — needs geometry. Verified manually /
  in-browser per §3.

Everything else in the WCAG 2.0/2.1/2.2 A+AA + best-practice rule tags is evaluated, and the
harness **fails the test on any `serious` or `critical` violation**.

## 2. Using the harness

```js
import { render } from '@testing-library/react';
import { expectNoA11yViolations } from '@/test/a11y';

it('has no serious/critical a11y violations', async () => {
  const { container } = render(<Thing {...props} />);
  await expectNoA11yViolations(container);          // fails on serious/critical
  // widen if needed:
  // await expectNoA11yViolations(container, { impacts: ['minor', 'moderate', 'serious', 'critical'] });
});
```

Render the component in each meaningful state (loading / empty / error / populated / open) and sweep
each — most a11y bugs hide in a non-default state. See the `*.a11y.test.jsx` files alongside the
Insights components for the pattern.

**Dependency:** `axe-core` (devDependency, pinned `^4.11.4`). It was already in the tree via
`@storybook/addon-a11y`; we promoted it to a direct dependency and call `axe.run` directly rather
than adding a wrapper lib (`vitest-axe`/`jest-axe`) — one axe version, minimal dependency surface
(RB-10 §12).

## 3. Per-surface manual-audit checklist

Automated coverage exists for the surfaces marked ✅ below; **every** surface still needs the manual
pass (the right-hand columns). Run each surface through:

- **SR** — screen-reader narration (VoiceOver / NVDA): every control announces a name + role +
  state; charts expose a text alternative / data table; status is never colour-only.
- **KBD** — keyboard only: full operability, logical tab order, no traps (except intended modal
  traps), visible `focus-visible` ring on every interactive element, Escape closes overlays.
- **ZOOM** — 200% zoom + 320px reflow (WCAG 1.4.10): no loss of content/function, no horizontal
  scroll on body text.
- **TGT** — target size ≥ 24×24px (WCAG 2.2 2.5.8) for icon buttons, chart slices, chips.
- **MOT** — `prefers-reduced-motion` honoured (RB-30 §5).
- **RTL** — mirrors correctly in an RTL locale (Cap A: Arabic).

- Drillable slices are real `<button>`s with descriptive names ("Open: 2 — show items").

## 4. Remaining work (tracked in #276)

This increment covers the **Insights** surfaces only. The same harness + manual checklist must be
extended to the rest of the app — Board, Backlog, Work-item detail, Sprint Cockpit, Admin Operations
Center, Developer Workspace, Customer Portal, Settings, the global shell (nav / command palette /
toasts), and the AI command bar. Add a `*.a11y.test.jsx` beside each surface as it is audited, and
tick its row in a per-area table like §3.

The full WCAG 2.2 AA audit is a **programme**, not a single PR: automated harness (done) → component
real-browser contrast pass (Storybook addon-a11y) → manual SR/KBD/zoom/target-size pass per surface
→ RTL pass. This document is the running ledger for that programme.

## 5. Fixes applied in this increment

- **`dashboard-drill-modal.jsx`** — was a `role="presentation"` overlay with an `aria-label` (a
  contradiction — `presentation` strips the name) and no dialog semantics or focus management. Now a
  proper **`role="dialog"` + `aria-modal` + `aria-labelledby`** with a focus trap, initial focus
  moved into the dialog, focus restored to the trigger on close, and a labelled backdrop button.
  Uses the **`z-modal`** token instead of `z-50` (RB-30 §9).
